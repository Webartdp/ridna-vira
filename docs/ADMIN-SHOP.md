# Адмінка та крамниця

Вхід: `/admin`. Публічної реєстрації немає. Доступ мають лише користувачі з `is_admin = true`, включно з локальним середовищем.

## Розгортання

Потрібні PHP 8.3+, розширення GD з WebP, Intl та стандартні розширення, які перевіряє Composer. Для обробки фото рекомендовано `memory_limit=256M` або більше. GD створює локальні WebP 400/800/1200, без збільшення оригіналу.

Збережіть резервну копію бази й завантажених файлів перед міграцією. У `.env` мають бути правильні робочі `APP_URL=https://ridnavira.com.ua`, `APP_ENV=production`, `APP_DEBUG=false`, база та поточний `APP_KEY`. **Не генеруйте новий APP_KEY:** ним зашифрований ключ WayForPay. Налаштуйте SMTP для листів про підтверджену оплату; за `MAIL_MAILER=log` листи лише записуються в журнал.

```bash
sudo -u ridnavira-com-ua -H /bin/bash -c '
set -e
cd /home/ridnavira-com-ua/web/ridnavira.com.ua/public_html/app
git pull --ff-only origin feature/site-build
composer install --no-dev --prefer-dist --optimize-autoloader --no-interaction
php artisan down --retry=60
php artisan migrate --force
php artisan storage:link
php artisan optimize:clear
php artisan site:import
php artisan filament:assets
php artisan view:cache
php artisan config:cache
php artisan route:cache
php artisan up
'
```

Composer встановлюється перед першою командою Artisan: після отримання нового коду Artisan уже потребує Filament. Якщо встановлення Composer завершується помилкою, спочатку усуньте її; не використовуйте `--ignore-platform-reqs`.

Якщо крок після ввімкнення режиму обслуговування завершується помилкою, сайт залишається в цьому режимі. Після виправлення повторіть потрібний крок і виконайте `php artisan up`.

Створіть першого адміністратора інтерактивно. Команда запитає ім’я, пошту та двічі пароль; пароль не передається в аргументах процесу й не виводиться:

```bash
sudo -u ridnavira-com-ua -H /bin/bash -c '
cd /home/ridnavira-com-ua/web/ridnavira.com.ua/public_html/app
php artisan site:admin
'
```

Один раз додайте Laravel Scheduler у crontab цього користувача. Команда нижче зберігає наявні завдання й не додає точний дублікат:

```bash
sudo -u ridnavira-com-ua -H /bin/bash -c '
set -e
entry="* * * * * cd /home/ridnavira-com-ua/web/ridnavira.com.ua/public_html/app && /usr/bin/php artisan schedule:run >> /dev/null 2>&1"
existing=$(crontab -l 2>/dev/null || true)
if ! printf "%s\n" "$existing" | grep -Fqx "$entry"; then
  printf "%s\n%s\n" "$existing" "$entry" | crontab -
fi
'
```

Без планувальника прострочені резерви не звільняються автоматично. Ручний запуск: `php artisan shop:expire-reservations`.

## Керування сайтом

Якщо вхід відхиляє почту чи пароль, запустіть через SSH `php artisan site:admin-reset`. Команда запитає пошту й новий пароль двічі, відновить прапорець адміністратора та змінить пароль. Якщо попереднє створення не завершилося, буде створено обліковий запис Admin. Пароль вводиться приховано; для цієї SSH-команди використовуйте латиницю, цифри та звичайні символи без пробілів, від 12 до 128 символів.

- **Сторінки** — основні сторінки сайту. **Новини**, **Статті**, **Творчість**, **Боги**, **Свята — тексти**, **Святині**, **Обряди**, **Молитви та слави**, **Книги**, **Документи** мають окремі пункти меню, власні списки та кнопки додавання. Тип матеріалу визначається вибраним розділом. Збережено пошук, чернетки, дату публікації, обкладинки, YouTube, попередні версії та кошик.
- Матеріали мають візуальний редактор. Блок «Молитва, славлення або обрядові дії» підтримує окреме оформлення та переноси рядків.
- Основні сторінки редагуються через список текстів, зображень і посилань із збереженням верстки. HTML доступний додатковим перемикачем. Позначки `[[live:…]]` залишають форми, мапу, каталоги й стрічки актуальними; їх слід зберігати.
- «Початковий вигляд» повертає імпортованій сторінці вивід оригінального шаблону. Редакторські версії залишаються в історії.
- **Громади та мапа** — міста, координати, назви, телефони й представники.
- **Календар свят** — редагування по місяцях. Зберігайте коди наявних адрес. Повний текст свята редагується в «Свята — тексти».
- **Файли та видання** — завантаження документів, аудіо й фото; адресу можна вставити в будь-який матеріал або список книг. Старі файли не видаляються автоматично.
- **Налаштування** — логотип, оголошення, меню з підменю, додаткові посилання, ресурси в підвалі, отримувачі листів і WayForPay. Облікові дані адміністратора змінюються через профіль. Оформлення можна тимчасово вимкнути; підтвердження вже здійснених платежів продовжать прийматися.

`site:import` обходить наявні локальні сторінки та їхні посилання, включно з пагінацією. Він не завантажує контент із зовнішнього порталу, не переписує редакторські зміни й не змінює існуючі адреси. На робочому сервері будуть додані також матеріали зі старих локальних сховищ, яких немає в Git. Недоступні старі документи позначаються попередженням і не створюються як порожні сторінки.

## Товари та замовлення

Товари додаються вручну. Створіть категорії, товар, артикул за потреби, ціну в гривнях, вільний залишок, опис і фотографії. Увімкніть «Показувати в крамниці». Демонстраційних товарів і стандартного адміністратора в міграції немає.

Кошик зберігає лише ідентифікатори та кількість. Ціни й наявність перевіряються на сервері. Замовлення фіксує склад, ціну, контакти й доставку, а товари резервуються на 30 хвилин. Повторне натискання оформлення не створює друге замовлення. При зміні залишку під час редагування товару адмінка просить відкрити його повторно.

Статус оплати не редагується вручну. В адмінці можна змінити виконання, внести номер відправлення й нотатки або скасувати неоплачений резерв. Відправити можна лише підтверджене оплачене замовлення. Повернення коштів виконується в кабінеті WayForPay; підписане повідомлення повного повернення оновлює замовлення. Фізичне повернення товару та поповнення залишку оформлюються вручну.

Перед відкриттям крамниці відредагуйте сторінку `/umovy-kramnytsi`: контакти продавця, умови доставки, обміну, повернення й обробки даних відповідно до фактичної роботи магазину.

## WayForPay

У «Налаштуваннях сайту й оплати» внесіть **Merchant Account**, домен і **Secret Key** з активованого магазину WayForPay. Ключ шифрується в базі й не повертається до браузерної форми. Порожнє поле зберігає поточний ключ. Також підтримуються `WAYFORPAY_MERCHANT_ACCOUNT`, `WAYFORPAY_SECRET_KEY`, `WAYFORPAY_MERCHANT_DOMAIN` у `.env`; значення з адмінки мають пріоритет.

Без налаштованих реквізитів оформлення вимкнене. Дані картки вводяться на `https://secure.wayforpay.com/pay`, а не на сайті. Тестові ключі в робочий код не внесені.

- `POST /oplata/wayforpay` — серверні підтвердження. Адреса передається в `serviceUrl` автоматично.
- `GET|POST /oplata/povernennia/{token}` — повернення покупця; воно саме не підтверджує оплату.
- Перевіряються HMAC-MD5 за протоколом WayForPay, merchant account, номер замовлення, сума й валюта. Відповідь `accept` також підписується. Повторні повідомлення обробляються без повторного списання товарів чи листа.
- Підтверджена оплата не понижується пізнішим повідомленням про відмову. Повтор `Approved` не скасовує статус повернення.
- Якщо підтвердження прийшло після звільнення резерву, замовлення позначається «Потребує перевірки», без повторного віднімання залишку. Перевірте товар і платіж перед відправленням.
- Приватне посилання замовлення має випадковий токен, не кешується й не індексується.

Інтеграцію реалізовано за [офіційним протоколом Purchase](https://wiki.wayforpay.com/view/852102). Живий платіж потрібно перевірити після налаштування вашого активного merchant account; локальні перевірки використовують підписані тестові повідомлення без списань.
