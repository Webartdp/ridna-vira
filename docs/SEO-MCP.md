# SEO та пряме підключення

SEO працює для всіх публічних HTML-сторінок через `SearchMetadata`: після рендерингу CMS формується один title і description, canonical, Open Graph, Twitter Card та JSON-LD. Для основних розділів підготовлено окремі українські тексти в `config/seo.php`; для матеріалів опис береться з основного тексту, для товарів — з опису товару. Нові сторінки також отримують автоматичні метадані.

У редакторі матеріалу є вкладка **SEO**. У товарах є поля **SEO: заголовок у пошуку** та **SEO: опис у пошуку**. Заповнені редактором поля мають пріоритет. `php artisan site:seo` заповнює лише порожні поля, не змінює текст, публікацію, дату оновлення та не вмикає CMS override. Після зміни теми чи змісту матеріалу перевірте заповнені SEO-поля; очистіть їх, щоб знову використовувати автоматичний опис.

Основне фото винесено на вкладку **Матеріал** у поле **Зображення**. Наявні локальні фото підтягуються під час відкриття форми, зміни записуються після збереження. Поле керує обкладинкою картки, основним фото сторінки та соціальним прев’ю. Додаткові фото й підписи залишаються в тексті. Для растрових завантажень створюються WebP-варіанти без збільшення оригіналу; картки використовують lazy loading, розміри та srcset.

Карта сайту: `/sitemap.xml`. Вона включає публічні розділи, наявні каталоги, CMS-матеріали й активні товари та виключає чернетки, майбутні публікації, видалені записи, кошик, замовлення й адмінку. `robots.txt` містить посилання на sitemap. Пагінація має власний canonical без рекламних параметрів. Фільтровані сторінки отримують noindex. Адмінка, кошик та замовлення мають X-Robots-Tag noindex. Структуровані дані містять тільки відомі факти; ціна й наявність товарів беруться з БД.

## Деплой

У `.env` має бути `APP_URL=https://ridnavira.com.ua`. Для MCP потрібно встановити нову залежність `laravel/mcp` із composer.lock: composer install виконується після git pull і перед наступними командами Artisan.

```bash
sudo -u ridnavira-com-ua -H /bin/bash -c '
set -e
cd /home/ridnavira-com-ua/web/ridnavira.com.ua/public_html/app
php artisan down
git pull --ff-only origin feature/site-build
composer install --no-dev --prefer-dist --optimize-autoloader --no-interaction
php artisan migrate --force
php artisan optimize:clear
php artisan site:seo
npm ci
npm run build
php artisan filament:optimize-clear
php artisan view:cache
php artisan route:cache
php artisan up
'
```

Після деплою відкрийте `/sitemap.xml`, перевірте вихідний HTML сторінки та поля **Зображення** / **SEO** в адмінці. Карту сайту можна подати у Google Search Console. Наявність метаданих не гарантує індексацію чи певну позицію в пошуку.

## MCP

**Endpoint `/mcp` реалізовано на офіційному Laravel MCP. Він стане доступним на робочому сайті після деплою вище.** Підключення Codex ще треба налаштувати на комп’ютері користувача. Публічний HTTPS має обслуговувати цей маршрут звичайним PHP/Laravel, без окремого порту чи фонового Node-процесу.

MCP приймає тільки окремий Bearer-токен чинного адміністратора. У базі зберігається SHA-256 хеш. Токен має термін дії, може бути відкликаний і перестає працювати, якщо користувач більше не адміністратор. Cookie-входу в адмінку недостатньо. Запити обмежені 60 за хвилину на IP та 6 MiB; сторонні Origin і неправильний Host відхиляються. Відповіді не кешуються, endpoint закрито від індексації. `APP_URL` має точно відповідати публічній адресі.

### Створення токена на робочому сервері

У прикладі нижче замініть `admin@example.com` на email свого адміністратора:

```bash
sudo -u ridnavira-com-ua -H /bin/bash -c '
cd /home/ridnavira-com-ua/web/ridnavira.com.ua/public_html/app
php artisan site:mcp-token create admin@example.com --name=codex --days=90
'
```

Останній рядок відповіді, що починається з `rv_mcp_`, — ваш токен. Він показується один раз. Скопіюйте його без лапок і пробілів у змінну Windows `RIDNAVIRA_MCP_TOKEN`. Не надсилайте токен у чат і не зберігайте в Git. Якщо втратили токен, відкличте старий і створіть новий.

Керування токенами з каталогу проєкту:

```bash
php artisan site:mcp-token list
php artisan site:mcp-token revoke --id=1
php artisan site:mcp-token create admin@example.com --name=codex-read --days=7 --read-only
```

ID для revoke береться з list. Без `--read-only` токен дозволяє читання, редагування текстів/SEO, заміну фото та публікацію. Пароль адмінки, бази даних або ключ OpenAI замість токена не підходить.

### Налаштування Windows і Codex

Натисніть Win+R → `SystemPropertiesAdvanced` → «Змінні середовища» → змінні користувача → «Створити». Ім’я: `RIDNAVIRA_MCP_TOKEN`. Значення: повний створений токен. Збережіть.

Додайте до `C:\Users\info\.codex\config.toml`, зберігши решту налаштувань:

```toml
[mcp_servers.ridnavira]
url = "https://ridnavira.com.ua/mcp"
bearer_token_env_var = "RIDNAVIRA_MCP_TOKEN"
```

Повністю закрийте та знову відкрийте Codex, щоб програма успадкувала нову змінну оточення. Якщо встановлено CLI, `codex mcp list` перевіряє наявність конфігурації; успішне читання матеріалу підтверджує реальне підключення й авторизацію. Перша команда в чаті: «Через MCP ridnavira знайди новини й прочитай одну. Нічого не змінюй».

### Доступні інструменти

| Інструмент | Призначення |
| --- | --- |
| `list-content` | Пошук, розділи, пагінація, включно з чернетками |
| `get-content` | Текст, SEO, обкладинка, статус, блоки та актуальна версія |
| `update-content` | Зміна вибраних текстів, SEO та блоків |
| `create-content` | Новий матеріал у розділі, завжди чернетка |
| `publish-content` | Окрема публікація, планування або приховування |
| `set-content-image` | Заміна основного фото через base64 JPEG/PNG/WebP до 4 MiB або його видалення |
| `list-content-revisions` | Попередні версії матеріалу |

Перед зміною потрібно викликати get-content й передати отриманий `version` як `expected_version`. При CONFLICT треба перечитати матеріал і врахувати чужі зміни. Для статичних сторінок використовуються існуючі ключі blocks, тому макет і динамічні блоки зберігаються. Для матеріалів — body_html. Основне фото змінюється окремим інструментом і отримує responsive WebP-варіанти.

Зміни опублікованого матеріалу відразу видно на сайті. Нові матеріали створюються чернетками; публікація — окрема операція. Мутації записуються в `site_mcp_audits`, попередній вміст — у звичайну історію CMS з автором-адміністратором. Токени, паролі та base64 зображень у журнал аудиту не записуються.

Можна працювати зі сторінками, новинами, статтями, творчістю, Богами, святами, святинями, обрядами, молитвами, книгами та документами, що вже імпортовані в CMS. Перший імпорт — `php artisan site:import`. Керування товарами, замовленнями, платежами, користувачами, довільні SQL/shell-команди та деплой цими інструментами не надаються.

### Якщо не підключається

- 401: перевірте повний токен, термін дії, відкликання та права адміністратора. Переконайтеся, що Codex перезапущений після створення змінної Windows.
- 400 Invalid host / 403 Invalid origin: перевірте APP_URL та домен підключення.
- 404: перевірте git pull, composer install, міграції та очистку/перебудову кешу маршрутів.
- При відкритті /mcp у браузері без токена очікувана відповідь 401; авторизований GET повертає 405. MCP використовує POST, тому браузерне відкриття не перевіряє працездатність інструментів.
- 429: зачекайте завершення хвилинного обмеження запитів.
- Якщо сервер бачить усі запити як 401 попри правильний токен, перевірте передавання заголовка Authorization від nginx/Apache до PHP. Сам токен у логах не виводьте.
